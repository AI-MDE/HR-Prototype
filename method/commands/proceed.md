# Proceed

`mde proceed [what]` (said to the agent)

The user's one word for "go on": start, continue, build, or move to the next stage, whichever the work needs now. Read the state of the work (`work/goal.md`, [`work/targets.json`](../metamodel/work/targets.md), `work/current/README.md`, `status.md`, `questions.md`) and do the first of these that applies:

1. **No Goal yet.** Record the Goal in `work/goal.md`, in the user's words (`mde proceed <goal>` gives it). Propose a Strategy that fits ([Prototype](../strategy/prototype.md), [Guided](../strategy/guided.md), or [Controlled](../strategy/controlled.md)); the user chooses, and it is linked in `work/current/README.md` (a choice the user already made is used without asking again). Say which [stages](../strategy/guided.md#stages) the work takes and which it skips, record the Goal's scope in its front matter (`scope`, when it is part of the application), leave `work/targets.json` empty (`{}`) until the architecture is settled, and start the first stage. If there is no root `mde.json`, establish it first ([bootstrap](../bootstrap.md)).
2. **Questions answered, or defaults to take.** Put the resulting knowledge in the owning Specs, move each answered [Question](../metamodel/work/questions.md) under `## Resolved` with its outcome, keep the unresolved ones visible, and go on with the stage.
3. **A stage under way.** Continue it, as [How a stage runs](../strategy/guided.md#how-a-stage-runs) says: the Targets in scope whose *Applies when* matches what is built, the work recorded and traceable to its Specs, verification when the Strategy says so, Status reported. `mde proceed <what>` narrows it (a capability, an entity, a use case, a page). Verify each Target in the loop as its output is produced (`mde verify --current`: generate, verify, fix), running it yourself; never ask the user to run it. Set `started` on a Target's record in `work/targets.json` (its scope: `*`, a capability, or one requirement) as its work begins; when that work is done and it passes, set `completed` and say so in Status: from then on it is graded. Never set it for work that is not done, or does not pass.
4. **A stage done.** Proceeding is the user's approval of it. Record the approval in `work/current/status.md` under **Approved** ([Status](../metamodel/work/status.md)): the stage, the date, and its state at the time. A stage left failed or blocked is recorded so, with what is left open: moving on is the user's decision, not a pass. Under the [Controlled](../strategy/controlled.md) Strategy, say first that its checks have not passed, and record the user's waiver with the approval. Before approval, say which of the stage's Targets are completed, verified since, and audited since (their records in `work/targets.json`), and which are not. Then start the next stage: its Targets' records are started as their work begins.
5. **The last stage of a slice done.** When the Goal has more to build, the user starts the next slice: a capability's record under each Target it reaches in `work/targets.json`, started as its work begins; the earlier records stay as history.
6. **The last stage done.** Say whether the Goal looks achieved and what shows it; the user decides, and sets the next Goal.

Only the user proceeds: never infer it from silence or from the ability to continue. Natural language works as well ("go ahead", "looks good, carry on", "let's build a leave tracker").
