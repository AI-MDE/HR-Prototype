# Work

Work concepts describe how the work on an application is being done: the Goal it pursues, the Current Work, its Status, the open Questions, the Findings verification raised, the Release Notes it prepares, the Strategy that guides it, and the user's Reviews and Annotations from the Workbench. They live in the application's `work/` area.

Work records what was done and why; it is not durable application knowledge (that belongs in Specs) and not proof of the product's state (that belongs in Evidence).
