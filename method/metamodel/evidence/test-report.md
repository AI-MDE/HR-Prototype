# Test Report

The result of running one test suite (for example API, business rules, or UI): `evidence/tests/<suite>.md`, with screenshots under `evidence/tests/screenshots/<suite>/`, logs under `evidence/tests/logs/`, and the runner's raw results under `evidence/tests/raw/<suite>.json` (Cucumber, Playwright or Vitest JSON, or `{ "suite", "passed", "failed", "skipped" }`), from which the Evidence Package counts each suite's tests. Always generated by the run, never written; a run replaces its suite's previous report, screenshots, logs and raw output. `mde verify` writes `evidence/tests/mde-test.md` for the application's `mde:test` script, with the build log beside it. The [Evidence Package](evidence-package.md) summarizes each suite in one row (passed, failed, totals) and links here.

## Content

- The command that ran, its exit code, duration, and totals (passed, failed, skipped).
- One row per scenario: its name, the spec ids it covers (use case, business rule, operation, or page), the result, and a link to its log excerpt.
- For UI scenarios, a screenshot at the end of the scenario and at the point of failure; for the [end-to-end suite](../../features/testing/end-to-end-tests.md) (`evidence/tests/e2e.md`), a screenshot after each step that changes the screen, shown with the step, so the report reads as a storyboard of the use case.
- The build log, when the suite needed a build first.

Its rules and checks are in the [evidence](../../targets/app/evidence.md) Target.
