# Reusable live pages

## Purpose

Use the same working page implementation for prototyping and the application where appropriate.

## Applicability

Applies to relevant pages and UI interactions. Respect the selected UI architecture/profile; presentation guidance is advisory unless explicitly adopted as a requirement.

## Impact on web-ui

- A page works the same in the prototype and the application; prototype status describes maturity, not a separate screen to replace later.

## Audit

- Is each page one live page, the same in the prototype and the application?

## Detail

The fuller guidance behind what the Targets compile from this Feature, with examples. It compiles into no Target.

### Impact on ui-design

Design real interactions and contracts for the requested scope. Prototype status describes maturity and release intent; it does not require a separate mock screen or fake backend.
