# Change rationale

## Purpose

A reviewer can understand **what changed and why** — the documentation explains the change, not
just the end state.

## Applicability

Applies to documentation and evidence relevant to the requested scope. Durable application meaning belongs in Specs; execution findings and evidence belong in Work or configured reports.

## Audit

- Can a reviewer understand what changed and why from the docs?
  · evidence: change docs / walkthrough updates
  · when: static

## Detail

The fuller guidance behind what the Targets compile from this Feature, with examples. It compiles into no Target.

### Impact on documentation

Docs make the change and its reasoning legible to a reviewer. Screenshots/walkthroughs are
updated when UI behavior materially changes.
