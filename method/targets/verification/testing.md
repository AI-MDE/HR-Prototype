### Captured command output  `[feature: captured-command-output]`

- `captured-command-output/output-captured` Is every executable check's output captured as UTF-8 under `evidence/tests/logs/`, and does each suite driving the application capture its server log, showing the requests its scenarios claim?

### Measured code coverage  `[feature: coverage-threshold]`

- `coverage-threshold/coverage-real` Do reports come from the current run, with failures and not-executed scenarios visible? Is coverage instrumented for real, with its threshold explicitly adopted and unmeasured parts named?

### End-to-end tests with screenshots  `[feature: end-to-end-tests]`

- `end-to-end-tests/page-operations-tested` Is every page operation performed by a passing browser scenario (`mde verify`, Operations tested through pages: every operation, not some), and every page of the inventory used by one (Pages tested)?
- `end-to-end-tests/screenshots-left` Did every browser scenario leave its screenshots (`mde verify`, Screenshots: one set per scenario)?
- `end-to-end-tests/use-cases-walked` Does every use case with a screen have a scenario walking its main flow in a browser, with screenshots after each step and at failure?
- `end-to-end-tests/e2e-report-generated` Is `evidence/tests/e2e.md` generated by the run, each step with its screenshot, and is the run instrumented for coverage?

### Behavior scenario traceability  `[feature: gherkin-traceability]`

- `gherkin-traceability/scenarios-traced` Are behavioral scenarios readable and traced: each tagged with the spec it proves, and every entity operation with an endpoint also covered by a scenario?

### Readable test data  `[feature: readable-test-data]`

- `readable-test-data/rules-proven` Does every business rule have scenarios tagged `@rule:<id>`, where it holds and where it is refused, and every use case and entity operation a scenario (`mde verify`, Tests row)?
- `readable-test-data/terms-verified` Does every promise of every Feature the application applies have a passing scenario tagged `@feature:<id>/<promise>` on each object that applies it (`mde verify`, Features row)?
- `readable-test-data/storage-checked` With a database: is every entity's storage checked against the migrated database by a passing scenario (`mde verify`, Storage tested row: every entity, not some)?

### Required-operation UI coverage (§7)  `[feature: required-operation-ui-coverage]`

- `required-operation-ui-coverage/rendered-operations-performed` Does every role-permitted operation a page renders have a UI scenario that performs it in a real browser and asserts an observable outcome, with a screenshot from the run?

### Verification check classification  `[feature: static-vs-executable-classification]`

- `static-vs-executable-classification/unexecuted-visible` Are unexecuted and blocked checks visible, never shown as passed?

### Running the tests  `[feature: testing-running-the-tests]`

- `testing-running-the-tests/commands-recorded` Are test commands recorded and `mde:test` declared, with scoped tests run for the verification activity and the full required suite before guided release?

### UI execution screenshots  `[feature: ui-screenshots]`

- `ui-screenshots/screenshots-captured` Does every UI scenario have a screenshot from the actual run, pass or fail, with missing captures reported?

### Use-case execution evidence and report  `[feature: use-case-execution-report]`

- `use-case-execution-report/reports-current` Do reports come from the current run, with failures and not-executed scenarios visible?
- `use-case-execution-report/not-run-shown` Does every test report show not-run and skipped scenarios as such, and does every scenario name the spec ids it proves?
